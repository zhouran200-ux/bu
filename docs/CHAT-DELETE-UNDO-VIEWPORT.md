# 删除消息撤销后的视口恢复

## 根因

旧逻辑只保存删除消息及索引。删除屏幕末尾消息后，LazyColumn 会因总高度缩短调整滚动位置。撤销时旧代码读取可能尚未更新的 layoutInfo，只有消息不在屏幕内才滚动到它的顶部；消息可见时不恢复，因此丢失删除前的位置。

## 修复

PendingChatDelete 新增删除前的 ReadingPosition（首个可见条目稳定 key、列表索引和像素偏移）。撤销插回消息后解析稳定锚点，通过 requestScrollToItem 在下一次重测量时恢复视口，并关闭流式自动跟随，避免其覆盖恢复位置。不再启动读取旧布局的滚动协程，也不再通过“消息是否可见”决定是否恢复。

## 回归与审计

新增三项 Kotlin 回归用例：删除末尾可见消息、删除顶部锚定的长回答、删除唯一消息后撤销。它们验证恢复目标和像素偏移，不冒充 Compose 真机端到端测试。已有稳定 key 删除回退、插入重排测试保留。

本地只执行源码卫生、嵌套滚动与 diff 检查；不启动 Java/Gradle。Kotlin 测试交给 GitHub Actions，推送后不等待。

检查全部 PendingChatDelete 构造与使用、删除结算、撤销栏、流式跟随、阅读记忆和导航。移除旧 firstFull/lastFull/onScreen 恢复逻辑；保留其他手动历史定位及发送后的滚动，不修改数据库结构、持久化删除时机、Manifest、依赖或生成生命周期。

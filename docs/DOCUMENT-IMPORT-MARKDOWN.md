# 文档导入的 Markdown 转换修复

## 问题现象

导入文档后：分段与原文不一致（段落中间出现视觉分段），章节标题没有标题格式。

## 根因（均有代码证据）

1. **TXT 导入不做任何章节识别**：`parseTxtToMarkdown` 只做换行归一化与 `trim`，因此「第57章 剥皮」只是普通段落，永远拿不到标题样式。DOC（Word 97-2003）路径同样没有标题识别。
2. **DOCX 只认 Word 样式标题**：`parseParagraph` 仅把 `pStyle=Heading1..6` 变成 `#`；中文小说里手打的「第N章」是普通段落，不会被识别。
3. **分段错位的真正来源是长文分块**：没有标题时整篇被当作一个「章节」，超过 1200 字就交给 `chunkBySentence` 按**句子**切开，每块成为来源列表里的独立条目并各带间距，于是段中间凭空出现分段。此外单个超长段落也会被强行拆开。

## 修复

- **共享标题识别**：新增 `data/DocumentHeadings.kt`，统一「Markdown 标题」与「中文章节行（第N章/回/节/卷/部/篇）」两种规则；UI 侧 `documentSectionTitle` 改为委托它，删除重复正则。
- **纯文本转 Markdown**：新增 `data/PlainTextMarkdown.kt`。TXT 与 DOC 均先解码再规范化：每个非空行成为一个 Markdown 段落（原文几段就是几段），章行输出 `# 标题`，连续空行折叠；**保留行首缩进**（中文段首全角空格），只去行尾空白，去 BOM。
- **DOCX 补充识别**：段落没有 Word 样式标题时，若纯文本内容匹配章节行，同样加 `# `；已有样式标题与列表行为不变。
- **分块改为不切段落**：`chunkLongText` 优先按段落边界累积；单个段落超过阈值时**整段保留**（阈值 `maxChars * 5`），只有极端超长时才按**行**边界切分，仅当单行本身超长才退化为句级切分。这样分块不再在段落中间制造分段。

## 行为变化（有意为之）

- TXT：`"第一行\r\n第二行\r\n\r\n第三行"` → `"第一行\n\n第二行\n\n第三行"`（每行一段）。
- TXT：`"第57章 剥皮\n正文"` → `"# 第57章 剥皮\n\n正文"`。
- DOC：`旧文档.doc` → `"# 第一章 拥抱\n\n她终于明白，有些事情只能自己走完。"`。
- 章节行判定仍与来源页浮动标题一致：句中提到的「第58章的内容」不会变成标题。

## 按示例小说写定的转换规则

完整规范见 [PLAIN-TEXT-CONVERSION-SPEC.md](PLAIN-TEXT-CONVERSION-SPEC.md)，依据用户提供的真实小说（1509 行 / 150795 字节）逐条归纳：

- **章标题**：`第…章/回/节/卷/部/篇`，章后可无分隔符；章后内容 >30 字或含句末标点则不算标题。
- **场景分隔符**：整行只由 `…`/`.`/`·`/`—` 等符号组成（如 24 处 `……` 独占行）→ 转成 `---`。
- **段落**：空行、章标题、分隔符都是段落边界；上一行未以句末标点结尾时下一行续接同段（中文不加空格，拉丁文补空格）。
- **列表**：编号项各自成段，不与上一行续接。
- **空白**：段首尾空白去掉，连续空行折叠，去 BOM。

用该小说实测验收：`#` 标题 **12/12**、`---` 分隔线 **24**、列表 7 项独立、段落 1415、最长段 183 字。

## 边界与后续

- **已导入的旧笔记不会自动重写**：它们的正文仍是旧格式。重新导入即可获得标题与新分段；如需对既有笔记做一次性重规范化，需要另行确认（会改写用户数据）。
- 若某些 TXT 是「硬换行」（一个段落被拆成多行），逐行成段会多出分段。可按需要改成「上句未以句末标点结束则续接」的规则。
- 真实排版观感（标题字号、段间距）需真机确认。

# 对话模型选择弹窗审计

## 已确认并修复

1. **同名方案身份冲突**：旧弹窗只返回名称，发送时 firstOrNull 按名称取第一个方案，可能使用错误端点与密钥。ApiProfile 新增持久 ID，旧 JSON 生成不含密钥的确定性 ID，重复 ID 修复；设置编辑保留 ID，对话按笔记保存 profile_id。旧名称仅用于第一次迁移，显示、选择和请求都用同一解析器。
2. **候选模型不一致**：旧计数/展开只用 selectedModels，点击和请求又回退 model。统一 availableModels 去空、去首尾空格、去重并包含旧主模型；无模型方案明确提示且不可选，单模型直接选，多模型展开，数量与实际候选一致。
3. **配置更新与请求竞争**：旧请求直接用 selectedModel，等待 LaunchedEffect 校正期间可能将旧模型搭配新方案。请求发起时重新以当前配置解析 ID 与合法模型，UI 同样直接显示解析结果。
4. **下标展开与长列表**：旧 expandedProfileIndex 随重排指向错误方案；展开模型嵌套普通 Column，单个方案内所有模型一次布局。改为持久方案 ID 展开、当前方案初始展开、稳定 key，模型逐项 LazyColumn 呈现，管理入口也在可滚动范围内。
5. **长名称挤占控件**：方案名、模型名使用受约束权重及省略行数，数量/勾选独立保留空间；条目最小触摸高度48dp，模型使用 selectable 暴露选中状态。底部入口显示当前模型，避免同方案内切模型看不出变化。
6. **API 管理路由丢失**：SettingsNav 原先只调用临时 handler，设置页未挂载时请求消失。先写入 AppNavigation.settingsRoute，再通知已挂载处理器。

## 保持不变与边界

生成中的请求使用启动时的方案/模型快照，弹窗切换只影响下一次发送，不取消或重启当前回复。不同笔记继续独立保存选择。资料提示词、推理参数和流式取消生命周期不变。

旧版本只保存名称，无法反推此前究竟选过哪个同名方案；第一次迁移沿用旧版首个同名规则，用户重新选一次即可建立明确 ID。删除已选方案仍保留既有“回退首个方案”策略。API 密钥可用性、远端是否提供模型需真实请求验证，弹窗不能替代供应商校验。

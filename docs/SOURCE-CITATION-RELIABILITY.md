# 可靠原著溯源修复任务

## 目标与边界
宁可明确拒绝引用，也不能将旧引用或非法引用定位到新剧情。复用现有导入、Markdown、分页和阅读器，不引入新的服务端、向量库或数据库迁移。能定位不代表证据支持结论。

## 阶段一：版本身份与失败关闭（本轮实施）
- 用 SHA-256 替代 String.hashCode，版本格式为 v1-加64位十六进制摘要。
- 摘要输入包含索引算法版本、600/900切片配置、标题与正文。字段使用长度前缀，避免拼接歧义。以后改变标签/边界算法必须升级索引版本。
- 旧十六进制版本仍可解析和显示，但不能自动迁移为新版本，也不能继续精确跳转。
- 来源编号必须是正Long；溢出、零或非法完整引用直接失败，不回退到单来源简写。
- 未携带来源或版本的引用仅可展示，不从当前资料补造历史版本。
- 版本不匹配停止跳转；来源不属于当前笔记本停止跳转。保留原回答，可手动阅读当前资料。
- 回归覆盖：合法新引用、旧格式显示、来源溢出/零、简写拒跳、版本过期、来源不符、标题改变、已知Java哈希碰撞、摘要稳定性。

## 阶段二：统一原文范围（待实施）
- 同一逐行扫描同时产生章节、段落、切片与阅读块的半开区间[start,end)。偏移基于原始存储Markdown的UTF-16索引。
- 不用整理后的文本反查原文；删除indexOf失败后猜cursor的路径。无法证明范围时返回失败。
- 围栏内标题不创建章节；处理CRLF、缩进、连续空行、重复文本和已有人工标签。不得改变正文或丢失字符。
- 明确600为目标、900为软阈值、1800目前是硬截断；旧文档“不在句中切断”并非真实代码行为。修改规则前写测试，之后升级索引版本。
- 人工标签识别、校验、复用单独验收，不能重复加标签造成模型歧义。

## 阶段三：范围高亮与索引性能（待实施）
- 用切片[start,end)与阅读块求区间交集，不只取起点；跨块引用应标出全部相关区域。
- 保持已有阅读块粒度，不以重写阅读器代替精确映射。
- 索引后台构建，按来源+版本缓存；设容量与失效策略，正文更新和删除释放旧索引。不得在每次点击时于主线程扫描百万字。
- requestId仍用于重复点击；只有页面可见后启动高亮计时；跳转目标需消费，避免重新进页面抢回旧位置。

## 阶段四：Markdown、流式与交互（待实施）
- 引用作为行内token解析，尊重行内代码、代码围栏、粗体和普通链接，不先切碎Markdown再解析。
- 原始标记持久化；脚注号按一次回答内首次出现排序，完整引用按规范化身份去重；代码里的标记不占脚注号。
- 半截标记流式缓冲有长度上限；结束时损坏标记明确显示，不吞正文。
- 失效态与正常态区分；补来源标题和引用号无障碍描述、手动来源切换、足够点击区域。
- 固定规则+稳定带标签全文在前；自定义设定、思考规范、历史和用户输入在后。不承诺缓存命中率或未经实测的token开销。
- 提示词区分“未找到依据”与“原著未写”，声明资料是数据非指令；分析附依据，RP新增内容不伪装成Canon。

## 验收与提交
阶段一先完成相关单测、增量Release编译、源码卫生。阶段二扩大到分块/转换测试，阶段四补Markdown与设备点击测试。禁止本地打包APK。真机验证、缓存回执测量与云端结果分开报告。
